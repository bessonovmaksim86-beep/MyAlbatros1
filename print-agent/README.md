# Агент печати этикеток

Агент печати запускается на компьютере кладовщика и передаёт номера
партии в локальный BarTender, который стоит на том же компьютере.

Сервер приложения (Spring Boot) работает на удалённой машине, и
запустить BarTender на компьютере пользователя напрямую не может —
браузер не даёт веб-странице запускать программы, а сервер не видит
установленный у кладовщика BarTender и его принтер.

Поэтому на машине кладовщика ставят этот агент: страница обращается
к нему по адресу 127.0.0.1:7788, а агент запускает локальный
bartend.exe с нужными параметрами.

## Требования

- Java 17 или новее (JRE достаточно). Проверка: `java -version`
- BarTender Suite 2022 (или совместимая версия)
- Шаблон этикетки `.btw` с полями:
  `NUMBER, INDEX, CLASSIFIER, NAME, ORDER, SHOWTEXT`
- Принтер этикеток, подключённый к компьютеру (или сетевой принтер)

## Схема работы

```
Компьютер кладовщика                     Сервер приложения
┌──────────────────────────┐            ┌────────────────────┐
│ Браузер                  │            │ Spring Boot        │
│  http://10.0.0.127:8080  │──HTTP─────▶│ 10.0.0.127:8080    │
│                          │            └────────────────────┘
│  fetch → 127.0.0.1:7788  │
│         │                │
│         ▼                │
│  Агент печати            │
│         │                │
│         ▼                │
│  BarTender → принтер     │
└──────────────────────────┘
```

Кладовщик открывает приложение по адресу сервера
(`http://10.0.0.127:8080`), а печать вызывает на **своём** компьютере
через `127.0.0.1:7788`. Поэтому в настройках сервера указывается
именно `http://127.0.0.1:7788` — этот адрес браузер кладовщика
понимает как его собственный компьютер, а не как сервер.

Адрес `http://10.0.0.127:7788` указывать **нельзя**: на сервере
агента нет, и порт 7788 там закрыт.

## Установка

1. Скопируйте на компьютер кладовщика **две вещи** (например, в
   `C:\print-agent\`):

   | Файл | Зачем |
   |---|---|
   | `print-agent.jar` | сам агент — один файл, ничего не потеряется |
   | `run-agent.bat` | запуск двойным кликом |

   Плюс создайте рядом `agent.properties` (образец лежит в этой папке).

   > Раньше агент состоял из двух `.class`-файлов, и если скопировать
   > только `PrintAgent.class`, окно писало `Agent stopped` с ошибкой
   > `NoClassDefFoundError: PrintAgent$Config`. Теперь достаточно
   > одного jar-файла. Отдельные `.class` тоже поддерживаются, но
   > копировать нужно оба.

2. Откройте `agent.properties` в блокноте и укажите пути:

   ```properties
   bartender.path=C:\Program Files\Seagull\BarTender 2022\BarTend.exe
   template.path=C:\BarTender\yacheika.btw
   ```

   Остальные параметры обычно не меняются. Если принтер не указан
   — BarTender использует принтер, записанный в шаблоне.

3. Сохраните файл и запустите `run-agent.bat`.

4. Проверьте: откройте в браузере
   `http://127.0.0.1:7788/health` — должен вернуться JSON с
   `"ready":true`.

5. **Важно:** агент должен работать на том же компьютере, где открыт
   браузер с приложением. Если страница открыта на машине кладовщика,
   а `run-agent.bat` запущен на сервере, браузер будет искать агент
   на машине кладовщика и не найдёт его.


## Автозапуск при входе в систему

Чтобы агент запускался автоматически при входе кладовщика:

1. Создайте ярлык `run-agent.bat`
2. Поместите его в папку автозагрузки:
   `C:\Users\ИмяПользователя\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\`

Агент можно настроить на тихий запуск (без окна консоли) через
`RunAgent.vbs` — см. ниже.

## Диагностика

- Логи агента: `print-agent.log` рядом с `agent.properties`
- Проверка готовности: `http://127.0.0.1:7788/health`
- Если агент не отвечает — проверьте, запущен ли процесс `PrintAgent`
  в Диспетчере задач, и есть ли Java в PATH.

Ответ `/health` показывает, что агент прочитал на самом деле:

```json
{"ok":false,"ready":false,
 "configFile":"C:\\agent\\agent.properties",
 "configFound":true,
 "keys":"port,bartender.path,template.path",
 "bartender":"C:\\Program Files\\Seagull\\BarTender 2022\\BarTend.exe",
 "template":"",
 "message":"Не задан путь к шаблону этикетки (ключ template.path). …"}
```

- `configFound: false` — файла настроек в папке агента нет, правки в
  другом файле агент не увидит;
- `keys` — какие строки агент распознал. Если нужного ключа в списке
  нет, значит в файле он написан иначе или файл не тот;
- `bartender` — какое значение ключа `bartender.path` реально прочитано.

Частые случаи:

| Симптом | Причина и что делать |
|---|---|
| В окне `'ava' is not recognized`, `'тановлен.' is not recognized`, `The system cannot find the drive specified` | Файл `run-agent.bat` повреждён редактором: сохранён в UTF-8 с кириллицей или с окончаниями строк LF. Скопируйте исходный файл заново |
| `ERROR: Java not found` | Java не установлена или её нет в PATH. Скрипт сам ищет её в `C:\Program Files\Java`, `Eclipse Adoptium`, `Microsoft`, `Amazon Corretto`, `BellSoft`. Если не нашёл — установите Java 17+ |
| «Агент печати не запущен на этом компьютере» | Окно `run-agent.bat` закрыто или агент не стартовал. Запустите заново, проверьте `/health` |
| «Не задан путь к bartend.exe», хотя путь в файле прописан | Агент читает не тот файл или не тот ключ. Смотрите `configFile` и `keys` в `/health`. Ниже разбор всех причин |
| «BarTender не найден по пути…» | Опечатка в `bartender.path`. Скопируйте путь из проводника: Shift + правой кнопкой → «Копировать как путь» |
| «Шаблон этикетки не найден…» | То же для `template.path`; проверьте, что `.btw` скопирован на эту машину |
| Кнопка есть, но при нажатии ничего | F12 → Консоль в браузере. `CORS` или `Private Network Access` — агент не ответил; `Failed to fetch` — агент не запущен |

### «Путь к bartend.exe не задан», хотя он прописан

Агент читает `agent.properties` один раз при запуске. Если в `/health`
в поле `bartender` пусто, значит значение не дошло. Четыре причины,
все встречаются на практике:

1. **Файл не тот.** Правки нужно вносить в `agent.properties` той папки,
   откуда запущен `run-agent.bat` (рядом с `PrintAgent.class`). В `/health`
   это видно по `configFile` — сравните путь с папкой, которую правите.
2. **Файл не перезаписан после правки.** Агент перечитывает настройки
   только при старте: закройте окно агента и запустите `run-agent.bat`
   заново.
3. **Другое расширение.** Windows скрывает «.txt», и Блокнот сохраняет
   `agent.properties.txt`. В журнале появляется отдельная строка с этой
   подсказкой. В проводнике: Вид → «Расширения имён файлов».
4. **Другое имя ключа.** Агент ждёт ровно `bartender.path`. Ключи вида
   `bartend.path`, `bartender_path`, `path to bartender` игнорируются —
   агент пишет об этом в журнал и упоминает похожий ключ в ответе
   `/health`. Регистр букв в имени ключа значения не имеет
   (`BarTender.Path` подойдёт).

Кодировка файла может быть UTF-8 (в том числе с BOM) или «Юникод»
(UTF-16) — обе Блокнота определяются автоматически.


## Тихий запуск (без окна консоли)

Если не хотите видеть окно консоли, создайте файл `RunAgent.vbs`
рядом с `run-agent.bat`:

```vbs
Set WshShell = CreateObject("WScript.Shell")
WshShell.Run "run-agent.bat", 0, False
```

Двойной клик по `RunAgent.vbs` запустит агент в фоне.

## Структура файлов

При копировании на компьютер кладовщика нужны **три файла**:

```
C:\print-agent
├── print-agent.jar          ← агент (один файл)
├── run-agent.bat            ← запуск
└── agent.properties         ← настройки (пути, порт, токен)
```

`print-agent.jar` содержит оба класса (`PrintAgent` и `PrintAgent$Config`),
поэтому его нельзя скопировать частично. Если по какой-то причине
приходится копировать отдельные классы — нужны **оба**:
`PrintAgent.class` и `PrintAgent$Config.class`.


## Почему run-agent.bat только на английском и с CRLF

Скрипт намеренно записан знаками только ASCII и с оканчиванием строк
Windows (CRLF). Причина — обе проявились на практике:

- **Кириллица в `.bat` ломает разбор.** cmd.exe читает файл в кодовой
  странице консоли (CP866), а файл сохранён в UTF-8. Русская строка
  превращается в набор байтов, часть которого cmd принимает за команды:
  вместо сообщения появляется `'тановлен.' is not recognized as an
  internal or external command`.
- **Окончание строк LF вместо CRLF** сдвигает буфер чтения, и команды
  обрезаются с начала: `java` превращается в `'ava' is not recognized`.

Поэтому сообщения самого скрипта — на английском, а русский текст
выводит агент (Java пишет его в UTF-8, а скрипт перед запуском ставит
`chcp 65001`). Если редактировать `run-agent.bat`, сохраняйте его в
ASCII и с CRLF — иначе печать перестанет запускаться.

## Формат файла данных

Агент записывает файл данных в том же формате, что и серверная
печать. Строка заголовка и по строке на номер:

```
NUMBER	INDEX	CLASSIFIER	NAME	ORDER	SHOWTEXT
500100001	1	5001	Подсборка ЯПР56	2026-0101	1
500100002	2	5001	Подсборка ЯПР56	2026-0101	1
```

Разделитель — табуляция (настраивается в `agent.properties`).

Шаблон `.btw` должен импортировать этот файл как источник данных.
Поле `SHOWTEXT` управляет выводом числового номера текстом над QR.

## Настройка сервера

На сервере приложения укажите адрес агента:

```yaml
application:
  label-printing:
    agent-url: http://127.0.0.1:7788
    agent-token: ваш-секретный-токен
```

Агент должен получить тот же токен:

```properties
token=ваш-секретный-токен
```

Если токен задан, агент принимает печать только с заголовком
`X-Print-Token` с этим значением.

## Безопасность

Агент слушает только 127.0.0.1 (петлевой интерфейс). Из локальной
сети к нему невозможно подключиться. Однако любой сайт в браузере
на этом компьютере может обратиться к агенту — токен предотвращает
случайные запросы от других расширений или страниц.

Отдельно учтена защита Chrome Private Network Access: страница
открыта по адресу сервера в локальной сети, а печать вызывает
агента на 127.0.0.1 — для браузера это переход в локальную сеть.
Агент отвечает заголовком `Access-Control-Allow-Private-Network: true`,
без которого Chrome блокирует такие запросы.

Если браузер всё же блокирует печать, проверьте консоль разработчика
(F12): сообщения вида `blocked by CORS policy` или
`Private Network Access` означают, что запрос не дошёл до агента.
