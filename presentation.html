Постановка задачи

⚠ Проблема

Разрозненные таблицы Excel и бумажные чек-листы. Невозможно отследить, кто, когда и по какой операции изготавливал конкретное серийное изделие. Данные теряются между подразделениями.

✓ Решение

Единая веб-система, в которой заказ клиента прослеживается до конкретного серийного изделия и обратно — из номера изделия видно исполнителя, дату и результат контроля.

1 Справочники

Классификаторы изделий, техпроцессы, маршруты операций

2 Планирование

График выпуска, распределение по подразделениям и исполнителям

3 Исполнение

Фиксация факта, контроль параметров, входной и тех. контроль

⛔ Официальная браковка

  • Раньше дефект снимали с работы «на словах» — след терялся
  • Причина брака тренируется через справочник дефектов
  • Факт контролируемого параметра «про ячейку» блокирует браковку
  • Оба решения уводят ячейку в изолятор брака

📦 Состав заказ-комплектующего

  • Кладовщик вписывает номер ячейки прямо в карточку операции
  • Проверки: лежит на складе, не в чужом заказе, не сверх плана
  • Состав читается одним пакетным запросом — без N+1
  • Снятие фактов: REWORKED с пустой датой — история цела
// Снятие фактов с ЗНП: история сохраняется, счётчик доукомплектования поднимается сам
for (ProductSerialOperation row : performedRows) {
  row.setStatus(ProductSerialOperationStatus.REWORKED);
  row.setActualDate(null); // chk_pso_reworked_has_no_actual
} // связь матрицы удаляется ПОСЛЕ снятия фактов

Нетривиальные решения

📐 Планирование графика

Обход маршрута в топологическом порядке. Операция не начнётся раньше предшественников + переходные дни. Мощность этапа — сотрудники × 8 ч. Загрузка считается по каждому экземпляру отдельно.

📝 Журнал перемещений

Единая точка записи. Модуль не обязан знать чужие детали — правило «какое событие и с какими реквизитами» живёт в одном сервисе.

🔒 Порядок правил Security

Spring Security берёт первое совпадение. Частные правила распределения работ стоят раньше общего блока цеха. Каждая граница описана комментарием в конфигурации.

// SecurityConfig — порядок matcher'ов важен
http.authorizeHttpRequests(auth -> auth
  .requestMatchers("/dispatcher/assign/**").hasRole("DISPATCHER")
  .requestMatchers("/workshop/**").hasRole("WORKSHOP") // общий блок — ниже!
);
